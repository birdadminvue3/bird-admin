## 登录 Maximum call stack size exceeded 修复
- **根因（已用 vue-router 4.5.1 + Node 脚本稳定复现 3 次）**：`src/router/index.ts` 的静态兜底路由 `/:pathMatch(.*)*` 写成 `redirect: "/dashboard"`。动态路由在守卫里才注入，注入前访问 `/dashboard` 也命中兜底路由并被 redirect 到 `/dashboard` 自身，Vue Router 的 `pushWithRedirect` 自递归直至栈溢出。**关键点：这个递归发生在进入导航守卫之前**，所以守卫里的防护完全不起作用。登录成功后 `router.push(redirect)` 必然踩中。
- **第二处隐患**：守卫里 `next({ ...to, replace: true })` 把整个 `RouteLocationNormalized`（含 `redirectedFrom`/`matched` 内部字段）传回 next，是 vue-router 官方反模式，同样可能触发重复 resolve。已改为 `next({ path: to.path, query: to.query, hash: to.hash, replace: true })`。
- **修复**：新增 `src/views/error/404.vue`；兜底路由改为 `component: NotFound`（不再自重定向）；`router/index.ts` 两处按上述改法。修复后同一脚本 3 次均正常到达 `/system/user`，刷新直达 `/dashboard` 也正常。
- **验证**：`pnpm lint` 0 错误、`pnpm build` 成功；dev 下 `/`、`/src/router/index.ts`、`404.vue`、登录页模块均 200；登录接口与 `/auth/routes` 正常返回两个父级菜单。
- **排查方法论**：浏览器自动化不可用时，用 `node --input-type=module` + `createRouter(createMemoryHistory())` 直接驱动 vue-router，复刻真实路由表与守卫即可稳定复现/验证，堆栈中 `pushWithRedirect` 连续重复是关键特征。
