# 2026-11-19 工作日志

## 代码全量审查（bird-admin 前端脚手架）
- 技术栈：Vue3.5 + Vite7 + TS5.8 + Pinia3 + Element Plus + pnpm10，约 3600 行源码，核心是 `src/utils/request` 请求封装。当前处于早期脚手架阶段。
- 实测结论：`pnpm build` 失败（`vue-tsc -b` 报 9 个 TS 错误）；单独 `npx vite build` 也失败（`src/views/empty/index.vue` 引用不存在的 `back.svg?component`）。**项目当前无法产出生产包**。
- 关键缺陷：登录提交逻辑被整段注释、路由守卫只有 `next()` 无鉴权、Pinia 未在 main.ts 注册（组件内无参 useStore 会抛错）、token 并发刷新失败时订阅者永久挂起、离线队列用裸 fetch 重放且 resolve 响应体而非 config、`download()` 仅支持 4 种 content-type、API 路径 `/api` 双前缀、环境变量 `VITE_API_URL` 与代码使用的 `VITE_API_BASE_URL` 不一致、dev proxy target 为空、mock `enableProd: true`。
- 已验证的库行为（避免误判）：`axios.getUri({baseURL:'/api',url:'/api/users'})` → `/api/api/users`；axios mergeConfig **会**合并自定义 `requestOptions`，传部分选项不会丢默认项；TS5.8 下 `async foo(): void` 报 TS1064，需写 `Promise<void>`；Pinia 无 activePinia 时无参调用 store 抛 `getActivePinia()` 错误。
- 本次仅审查，未修改任何源码；输出问题清单与 P0/P1/P2 修复优先级。

## RBAC 权限管理 mock 接口（同日完成）
- **关键坑**：`vite-plugin-fake-server@2.2.0` 会对每个 mock 文件**单独 bundle**，模块级变量不共享；跨接口 CRUD 必须把共享状态挂到 `globalThis`（本例 key `__BIRD_ADMIN_RBAC_DB_V1__`），否则新增用户在登录接口里不可见。
- **数据模型**：菜单（M 目录 / C 页面 / F 按钮）→ 角色（含 menuIds/dataScope/status）→ 用户。按需求实现父级 `控制台 /dashboard`、`系统管理 /system` 与 6 个子菜单（menu/role/user/dept/post/dict），按钮权限形如 `system:user:add`，超管 `*:*:*`。演示账号 admin/system/auditor/guest 权限依次递减。
- **接口**：`mock/rbac/{auth,menu,role,user,dept,post,dict}.ts`，统一 `{code,data,message}`；认证 `/login`、`/auth/{refresh-token,getUserInfo,routes,logout}`；资源 CRUD + `/role/:id/permissions`、`/user/:id/roles`、`/user/:id/password`、各 status 切换；分页用 `pageNum/pageSize`，业务码 401/403/404/10002/10003/10005/10006。旧 `mock/login.ts` 已删除避免路由冲突。
- **前端**：`src/api/rbac/*` typed 客户端；`permission` store 把 `/auth/routes` 转 `RouteRecordRaw` 并 `addRoute`（component 标识映射表在 store 内登记）；路由守卫刷新后先 `getUserInfo` 再生成路由；`v-permission` 指令控制按钮；layout 补侧边栏 + `router-view`；`src/views/system/resource/index.vue` 用一套 schema 渲染 6 类资源页；删除静态 `home.ts` 避免 `/dashboard` 冲突。
- **验证**：lint/build 通过且生产包无 mock 残留；dev 实测 22 项只读/权限断言 + 33 项 CRUD/授权断言全部通过（含角色授权后用户登录能拿到对应菜单与按钮、403/401、停用登录拒绝、冲突校验、分页筛选）。注意首次加载新 Element Plus 组件时 Vite 重优化依赖触发沙箱批量删除保护导致 dev 进程退出，重启后稳定，非代码问题。
