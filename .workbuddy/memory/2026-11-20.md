## 多仓库同步脚本（Gitee + GitHub）
- **诉求**：同一份代码同时维护 gitee（https://gitee.com/web_akai/bird-admin.git）与 github（https://github.com/birdadminvue3/bird-admin.git），要一个上传脚本。
- **实现**：新增 `scripts/sync-repos.mjs`（Node ESM，零依赖，Windows/macOS/Linux 通用），`package.json` 加 `sync` / `sync:dry` 两个 script；README 增加「多仓库同步」章节并挂到目录。
- **关键设计**：
  - 远端按 **URL 归一化匹配** 复用已有 remote：gitee 命中现有的 `origin`，不会重复加一个 `gitee`；github 不存在时自动 `remote add github`，同名不同地址则 `remote set-url`。
  - 推送用显式 refspec `refs/heads/x:refs/heads/x`，不依赖 upstream 配置；按仓循环、单个失败不中断，最后汇总并用退出码区分（0/1）。
  - 工作区脏默认中止并列出文件；`--commit` 自动 `add -A` + 提交（消息可用 `-m`），`--allow-dirty` 只推已提交内容。
  - `-b/--branch` 多次指定分支、`--all-branches`、`-r/--repo` 只同步某个仓、`--dry-run` 只打印命令。
  - 认证优先系统凭据管理器；支持 `GITEE_TOKEN`/`GITHUB_TOKEN`（或 `GH_TOKEN`）注入到本次 push 的临时 URL，不写 `.git/config`，输出与 git 原始错误都做 `***` 脱敏。
  - 失败提示按关键字分类：non-fast-forward → `git pull --rebase`；Authentication failed → 配凭据/Token；Repository not found → 查地址权限；protected branch → 走 PR。
- **坑**：脚本里 `printHelp()` 在 `const c`（颜色函数）之前调用会触发 TDZ `Cannot access 'c' before initialization`——函数声明会提升但 const 不会，把 help 判断挪到颜色定义之后即可。eslint `no-useless-assignment` 会抓 `dirty = ...` 这种提交后的无用赋值。
- **执行结果（真实推送）**：`node scripts/sync-repos.mjs -r gitee --all-branches` 与 `-r github --all-branches` 均成功；`git ls-remote` 核对两端一致：`develop=b189a8b`、`master=8b095e3`。本机 GCM 已缓存两个平台的凭据，非交互也能推（验证时加 `GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never` 防止弹窗卡死）。
- **注意**：仓库里 `.env`、`.env.development`、`.env.production`、`.workbuddy/memory/` 均已被 git 跟踪（当前 `.env*` 只有 VITE_ 配置、无密钥）；后续加密钥类变量前要么改用 `.env.local` 并 ignore，要么先用 `git rm --cached`。master 分支未包含本次脚本提交（只在 develop），需要时再合并。
